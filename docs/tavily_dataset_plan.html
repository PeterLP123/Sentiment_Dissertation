Tavily Shared Dataset Plan For Later Sentiment Research

A plan for using Tavily to collect recent financial news source material, turn it into a traceable dataset package, and share it with colleagues before any modeling or labeling decisions are made.

Prepared: 2026-06-11 Repository: Sentiment_Dissertation Scope: Plan only, no data generated Audience: research colleagues Primary path: Data/news
1 Keep the Tavily corpus separate from the existing labeled benchmark.
2 Use Tavily Search and Extract to build up-to-date article corpora.
3 Package source text with query, source, date, and screening metadata.
4 Share a reviewable dataset pack colleagues can label or reuse later.

Recommendation

Use Tavily as a reproducible acquisition layer for current financial text, not as the source of sentiment labels and not as an immediate model-evaluation step. The best first output is a shared current financial news corpus: recent articles gathered by fixed query families, stored with source metadata, deduplicated by URL, screened for relevance, and packaged so colleagues can inspect the provenance before using it.

The immediate value is a clean dataset bundle that can be reviewed, extended, cited, and labeled later. That keeps the data-creation work useful even before the team agrees on a specific experiment.

Core rule

Build provenance first. Labels, model runs, and analysis claims should come later, after the shared corpus has been screened and its reuse rights are understood.

Why Tavily Fits This Repository

Current web coverage

Tavily Search supports news and finance topics, date filters, domain filters, and up to 20 results per request, which matches the need for small controlled corpus builds.

Article extraction

Tavily Extract can turn returned URLs into plain text or markdown. This is useful for storing article text separately from the current labeled benchmark and screening it before sharing.

Traceability

Tavily responses can include request IDs and usage information, and this repository already records manifests for generated news corpora.

Labeling Later

Keep v1 unlabeled

The first shared release should be a source dataset: URLs, metadata, snippets, screening notes, and optional extracted text. That makes it useful before the team agrees on label definitions.

Prepare label hooks

Reserve optional columns for future sentiment labels, labeler IDs, confidence, ambiguity notes, and adjudication status. Leave them blank in the initial package.

Agree before labeling

When the team is ready, define whether labels apply to the headline, lead paragraph, whole article, company, asset, or market implication. That decision should be written before anyone labels examples.

Important boundary

Do not merge Tavily-derived rows into Data/data.csv. Keep them as a separate derived dataset so the team can decide later whether it is a source corpus, an annotation project, or a benchmark extension.

Initial Pilot

Day 1

Design and fetch

Select the configured query families, request 10 to 20 results per family for the last week or month, and keep extraction enabled. Target roughly 60 to 120 sources before screening.

Day 2

Screen and index

Deduplicate URLs, remove irrelevant or low-content pages, flag extraction failures, and record whether each source is suitable for colleague review.

Day 3

Package v1

Create a compact source table, screening index, dataset README, manifest copy, and optional extracts file if full-text sharing is acceptable.

Day 4

Colleague handoff

Share the package with colleagues, collect feedback on coverage and usability, then decide whether a v2 collection or a labeling pass is worth doing.

Quality Gates

Before fetching

  • Query families are named and versioned.
  • Date range and domain policy are fixed.
  • Target sample size is written down.

Before packaging

  • Duplicates and extraction failures are marked.
  • Inclusion and exclusion rules are documented.
  • Raw article bodies are separated from compact metadata.

Before sharing

  • Dataset README is complete.
  • License and redistribution risk are checked.
  • Full text is shared only when rights and audience allow it.

Main risks

The biggest risks are licensing restrictions, duplicated syndicated articles, broad queries that collect irrelevant pages, and sharing more article text than source terms allow. The plan controls these by separating compact metadata, optional extracts, screening notes, and later labeling decisions.

Implementation Scope Later

The repository already has a useful foundation through sentiment-bench fetch-news, news-check, and the Data/news output convention. The implementation should add sentiment-bench package-news to turn existing corpora into Data/derived/<package_id> share packages without making new Tavily calls.
